⑤ DeepGEMM 小 M：BLOCK_M 变小，Layout 不变

DeepGEMM 示例：sm100_fp8_fp4_gemm_1d1d.cuh 的非 swap、单 CTA、block-scaled FP8 路径（与 ⓪ 的选择无关），演示 workload M 对应的 BLOCK_M（本页固定示例，不是重新执行完整 get_best_config）。该源码中 LAYOUT_AD_M=128 → UMMA_M 恒为 128 → 结果布局恒为 Layout D（sm100_fp8_fp4_gemm_1d1d.cuh:49–50）；BLOCK_M=32/64 只改变取出几个 32 行区间。

workload M
SMEM A stage 并没有一律扩到 128 行。SMEM_A_SIZE_PER_STAGE = LOAD_BLOCK_M×BLOCK_K×sizeof(A)，BM=32 时就是 32 行（kernel:93）。UMMA_A_SIZE_PER_STAGE = align(LOAD_BLOCK_M,128)×… 只是校验 MMA 读取范围不越界的量（kernel:100），多读的行可能落在后续已分配的 A/B 缓冲（指针排布 kernel:139）。M=4 时 A tile 内 4…31 行是 TMA 越界填充，32…127 行不能认定为同一块显式补零。（行号均指 sm100_fp8_fp4_gemm_1d1d.cuh）
只读取 Layout D 的第一个 32 行区间并不等于 Layout G。四个分区也不意味着必须启用四个写回 warp：kNumUMMAStoreThreads = min(BM,128)，BM=32 只启用 1 个（kernel:86、479）。写回 warp 用 tcgen05.ld.sync.aligned.32x32b.x8 读回，线程 t 读 lane 32W+t（sm100_store_cd.cuh:120）。额外 MMA 行的比例（如 96/128）不能直接当作时间或能耗损失比例。完整 kernel 中结果列还要加上 accum_stage_idx×UMMA_N 的累加槽偏移（kernel:506）。
